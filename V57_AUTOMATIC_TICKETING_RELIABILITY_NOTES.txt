BASSE ONLINE SHOP V57 — Ticketing reliability and event admin fixes

Implemented in source:
- Physical/offline ticket batches are automatically marked payment_status=PAID and ticket_status=VALID at generation. QR check-in still changes VALID to USED exactly once.
- Online checkout accepts 1–10 tickets, computes the full Waychit payment amount, associates every ticket in the purchase with the same Waychit payment-request ID, and activates the whole purchase only after a valid signed completion webhook.
- Event deletion removes associated ticket records, ticket types, scanner access and organizer access in a single database transaction after an explicit admin confirmation.
- Admin event management has clearer event cards and a dedicated delete action; removed the redundant empty ticket-verification section.
- Scanner access now transitions directly to the dedicated scanner view and requests the camera; successful/failed scans have distinct visual states.
- Customer ticket purchase has a quantity selector and live Dalasi total, and avoids duplicate local ticket entries.
- Physical print labels now say PAID / PHYSICAL SALE / VALID FOR ENTRY, and the compact PDF layout keeps the flyer clear of the ticket code.

Production requirements:
- Render must have WAYCHIT_API_KEY and WAYCHIT_WEBHOOK_SECRET set.
- Waychit webhook destination: https://basseonlineshop.com/api/waychit/webhook
- PUBLIC_BASE_URL=https://basseonlineshop.com
- A signed Waychit completion webhook is the source of truth for online payment. A browser redirect alone does not prove payment.

Checks performed: ZIP integrity; Node syntax check for server; extracted inline JavaScript syntax checks for admin/services, marketplace/services and marketplace/scanner. Live Render database, real Waychit checkout/webhook, and device camera cannot be exercised in this local workspace.
